# System Workflow
-------------------------
The prototype follows a highly reactive execution pattern:

[INPUT] -> [TRIGGER DETECTION] -> [SEQUENTIAL PROCESSING] -> [OUTPUT]

1. **Input**: A workflow is activated via an App Event (Telegram), Webhook call, or a Manual Test Run from the UI.
2. **Trigger Detection**: The backend engine identifies the starting node and prepares the initial data payload (e.g., the text of a Telegram message or JSON from a webhook).
3. **Processing**: The execution engine traverses the workflow "edges." It handles AI Prompting (sending data to Gemini/OpenAI), conditional logic (If/Else), and utility tasks sequentially.
4. **Output**: Results are collected from "Result" or "AI" nodes. If the trigger was a bot, the final result is dispatched back to the external platform (Telegram) as a message or stored in the database.
